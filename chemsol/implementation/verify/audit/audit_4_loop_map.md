# Audit 4 — Process-Loop Alignment Map

> **Scope:** Maps every stage of the canonical process loop (SO → Costing → Project/Plan → MR gate → MIS → Production → FGHM → Site → P&L, plus Stream A procurement side-loop and cross-cutting automations) to the forms, key fields, automations (A-## register), and evidence reports (R1–R7) that serve it. Identifies orphan/scope-ambiguous items and cross-document contradictions.
>
> **Sources read:** root `AGENTS.md`, `chemsol/AGENTS.md`, `chemsol/IMPLEMENTATION_PLAN.md`, `chemsol/forms.html`, `chemsol/automation.html`, `chemsol/reports.html`, `chemsol/REPORT_IMPLEMENTATION_PLAN.md`, `chemsol/UAT_VERIFICATION_PLAN.md`, `chemsol/AUTOMATION_ALIGNMENT_PLAN.md`, `chemsol/implementation/verify/flow_sim.py`, `chemsol/files/*.csv` (Excel export).
> **Method:** Every loop stage traced end-to-end; automation IDs from the canonical A-01…A-43 register (AUTOMATION_ALIGNMENT_PLAN.md §2); report IDs from reports.html R1–R7 + REPORT_IMPLEMENTATION_PLAN phases M1–M7; UAT Step 1–10 + flow_sim P0–P5/P7/REP used as executable cross-checks.
>
> **Headline verdict:** All 9 loop stages + Stream A + cross-cutting satisfy the alignment standard (≥1 automation AND ≥1 report). No stage fails the gate. Findings are 3 BLOCKER-class (dual MR line tables, PO/GRN Project-ID requirement vs Stream A, P&L formula divergence), 6 FIX-class (stale residues), 5 INFO-class (scope decisions).
