Project-Centric ERP · Two-Stream Architecture

Implementation Plan

Stream A (Stock Procurement): PR → PO → GRN → QC — procurement for stock, no Project ID. Stream B (Project-Centric): SO → Costing Sheet (5 sections auto-expanded from SO × BOM) → Costing Approved (auto-creates Project + Production Plan) → MR auto-derived (4 cost components pre-filled) → Production Verified → Costing Approved → Released → MIS → Production (Job → BMR → Pack → FGHM) → Site Consumption → Material Return → Project P&L. MR is the critical gate — without Released MR, no downstream execution.

SO↔BOM↔MR cross-validation: Σ(Assigned Qty) vs Σ(SO Area × BOM Qty × (1+Waste%)) — mismatch > 5% flags for review, > 10% hard-blocks. 7. Phase 6 — Inventory Management

7.1 RM Inventory

  • Stock increased on GRN posting
  • Stock decreased on MIS posting
  • Stock alerts at Min/Max thresholds
  • Available Stock = physical stock − Σ(Assigned Qty from all unreleased MRs) — prevents double-allocation

7.2 FG Inventory

  • Stock increased on FGHM inline acceptance
  • Stock decreased on dispatch (Supply Only sales)
  • FG stock tracked per Project ID for project-level reporting

7.3 Project Inventory Status NEW Report

Each project tracks in real time:

  • Assigned Qty (from MR Material Allocation)
  • Issued Qty (from MIS — total issued to production)
  • Consumed Qty (from BMR + RM Consumption + Site Consumption entries)
  • Returned Qty (from Material Return)
  • Remaining = Assigned Qty − Consumed Qty + Returned Qty
  • Consumption % = Consumed Qty ÷ Assigned Qty × 100
  • 80% Alert status per RM line
Single source of truth for project P&L inventory calculation.

⛔ Gate: Without a Released MR, there is no MIS, no Production, no FGHM, no project execution. SLA: 2 hr per stage — Draft > 2 hr → reminder, Production Verified > 2 hr → escalation to Costing lead, Costing Approved > 1 hr → auto-release if checks passed.

8.2 Consumption → Project-Assigned RM

  • Every consumption entry (BMR/RM Consumption / Site Consumption) resolves to MR Allocation line matched by Project ID + Item Code
  • No generic pool deduction for project-tagged consumption
  • Site consumption entries are expanded into RMs at BOM ratios, then increment Consumed Qty
  • Material Return decrements Consumed Qty and credits back store stock

8.3 80% Consumption Alert

  • When Consumption % ≥ 80% AND 80% Threshold Alert Flag = ON
  • Pop-up + dashboard banner + email to Project Manager
  • At 100%: "Allocation Exhausted" alert fires to Project Manager + Purchase
  • Real-time — fires within 1 min of threshold breach (event-driven, not cron)

MR Verification Flow

Production verifies MR quantities against SO system requirements (checks MR line item qty vs expected RM from BOM × SO system qty). Then Costing approves the MR cost baseline (all four cost components). MR is Released only after both gates pass. SLA: 2 hr per stage, auto-escalation on breach.
